# Automatic product details from an Amazon link

Updated 6 October 2026.

The active importer is now `amazon-page`. Paste a full Amazon product URL or approved short link to fetch available title, description, feature bullets, specifications, brand/model, category, and main product image. Details are extracted from the listing rather than generated by AI. The former `owner-content` provider remains in source. The official API provider remains a dormant scaffold.

## Using the feature

1. Open Products → Add a product.
2. Paste the Amazon link into **Fetch product details**. No title or description entry is required.
3. Click **Fetch product details** and review the returned description, image, and expandable specifications.
4. Click **Apply all fetched details**, or choose individual fields and apply only those. This explicitly replaces selected editor fields. Missing details remain missing; unknown categories retain the current editor category. Applying an image clears any old Cloudinary upload ID.
5. Review the card preview and confirm the existing content/image permission assertion.
6. Save draft, then reopen the saved draft to review and publish normally.

Editing the link cancels and invalidates its previous preview. Closing the dialog cancels the request. Errors preserve the editor's values. Duplicate products are identified by marketplace/ASIN, including drafts and archived products.

## Available details

- Title, readable product description, and up to twelve distinct feature bullets (up to 1,000 characters each in the review).
- Up to forty product specifications, including brand and model when available. Both technical-specification tables and matching JSON-LD additional properties are read.
- Main image from an exact trusted Amazon image host. Images are referenced directly; the importer does not download them or upload them to Cloudinary.
- Category when breadcrumbs map clearly to an existing project category.

Imported copy passes through `shared/productCopy.ts`: promotional title fragments and trailing specification blocks are removed while model/generation identifiers remain. Descriptions become deduplicated, labelled facts within the existing 2,000-character limit. Source attributes work independently of product category: unfamiliar short labels are retained, specification rows take priority over marketing copy, and the old seven-row cutoff is removed. `shared/featureFacts.ts` replaces verbose feature paragraphs and promotional headings with concise source facts, using unit ranges and their nearby context. Examples include Screen compatibility, Supported weight, VESA mounting, Tilt, Swivel, Rotation, desk thickness limits, Material, Capacity, Power, Battery capacity, and Cable management. Promotional comfort/security promises, desktop-space percentages, and assembly-speed claims are omitted from the concise copy. Negative statements do not become positive feature claims. Unrecognized long prose is omitted when it cannot supply a short factual statement; full extracted features/specifications remain available in the import review for manual correction. Monitor and mouse parsing supplements this generic path and retains extra source attributes. Accessory nouns such as monitor arm or mouse pad prevent the compatible device's specifications from being treated as the accessory's own. Compatibility mentions alone do not classify a keyboard as a monitor or a scanner as a mouse. Decimal measurements and negative tilt limits remain intact. Related products, reviews, ratings, prices, and stock are not imported.

`src/components/ProductDescription.ts` renders specification labels in bold as semantic definition rows before remaining prose and escapes all listing text. Catalog cards and editorial sections show a short summary of the first three facts. Existing saved listings receive the same cleanup for storefront presentation without a bulk database rewrite. For example, the existing monitor is displayed as **Lenovo Legion R27qe Gen 2**, with separate Display, Refresh rate, Response time, and Connectivity rows.

The cleanup uses a local deterministic language parser, not a trained ML model or an external AI service. It recognizes source labels, product model tokens, and measurement units; it never generates missing specifications. Titles/rows should still be reviewed against the exact product listing during import. Previously truncated stored descriptions cannot recover lost specifications: for example, `12,000 D` is not treated as a verified DPI value. Re-fetching the listing can supply complete source facts.

The HEYMIX LIFE Single Monitor Arm (`B0CH4X2FVM`) had been saved with only `Display: 13-inch` and adjustability because the old formatter treated the word monitor as the product type. On 6 October, its exact Amazon listing was re-fetched through the authenticated development importer and this one development product's description was repaired. It now retains Mounting Type, Movement Type, Brand, Material, Colour, plus source feature details covering the 13–32-inch / 2–9-kg compatibility, VESA patterns, adjustment angles, and clamp/grommet thickness ranges. Original visible catalog settings were preserved. Its previous description and the fetched preview are backed up locally under `.tmp/`.

Persistence testing also exposed create-time defaults being applied to omitted PATCH fields. `shared/schemas.ts` now removes defaults before making fields optional, so publishing or updating one field preserves omitted descriptions, ratings, image references, affiliate overrides, and catalog settings. Verification of the concise-facts update: 35 unit tests and 23 integration tests passed; build/typecheck passed. These cover monitor arms, arbitrary source attributes, storage/home/toy/lighting categories, compatibility mentions, measurement decimals, negations, repeat formatting, and imported draft-to-published persistence. Local API readback confirmed the existing HEYMIX description renders as 380 characters of concise facts instead of 1,442 characters of feature prose (about 74% shorter), including 360° rotation and both desk-thickness ranges. This latest cleanup applies automatically to existing storefront copy and to new import suggestions without another database rewrite. Visual browser verification was unavailable in this session.

## Implementation

- `worker/lib/productImport/providers/amazonPage/provider.ts` fetches a canonical product page with an eight-second deadline and four-MiB response limit. Redirects must stay on the exact supported marketplace and requested ASIN; four attempts maximum. No user cookies or credentials are sent.
- `extract.ts` uses Cheerio's slim parser for product selectors and matching Product JSON-LD. It does not execute scripts. Wrong ASINs, CAPTCHA/verification pages, missing titles, and unusable responses produce clear errors rather than invented details.
- `worker/lib/productImport/resolveProductUrl.ts` expands approved short links with five redirects maximum and an eight-second deadline. Each destination must use HTTPS, an approved exact Amazon/short host, no credentials, and no custom port.
- `worker/lib/affiliateLinks.ts` replaces embedded tags with `AMAZON_ASSOCIATE_TAG` for the destination marketplace. A product's explicit owner tracking-ID override takes precedence. Previous `ascsubtag`/`linkId` values are removed when applying the owner's tag, then an explicit product sub-ID is applied. Product/variant parameters stay intact.
- `src/admin/ProductImportPanel.tsx` provides link-only fetch, result review, image preview, and selective/all-field application. Its cancellable deadline is 25 seconds to allow short-link expansion plus page fetch.

Preview requires owner authentication, same-origin CSRF validation, and a five-request-per-minute owner limit; it creates no product. Draft saving checks identity, image references, selected provider, and the existing content/image assertion, and enforces draft status. Concurrent assisted saves are serialized by marketplace/ASIN.

Migration 4 extends `product_content_sources` to distinguish `amazon-page` and `owner-content`. This records assisted creation provenance and the owner assertion, not independently verified reuse rights. Existing products are not rewritten.

## Setup and verification

Use the full development server:

```powershell
npm run db:migrate -- --target=dev
npm run dev -- --port 3010 --host 127.0.0.1
```

Migration 4 is applied to the development database. No production migration or deployment was performed; production migrations require the normal release process.

Build/typecheck and 46 targeted tests passed, covering extraction, structured data, wrong products, unsafe images/redirects, size limits, blocked pages, partial results, selective merging, affiliate tags, authentication/CSRF, duplicates, draft persistence, and existing store flows. Tests use authored HTML fixtures and disposable PostgreSQL. A real product fetched through port 3010 returned a title, description, five feature bullets, and an image without manual details.

Page fetching depends on Amazon serving readable HTML. Access refusals and CAPTCHA are surfaced; there is no proxy rotation, CAPTCHA bypass, login automation, or API fallback. Future official integration uses [Creators API documentation](https://affiliate-program.amazon.in/creatorsapi/docs/en-us/introduction); HTML parsing uses [Cheerio's documented loading API](https://cheerio.js.org/docs/basics/loading/).
